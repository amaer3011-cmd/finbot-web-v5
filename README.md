# موقع حل الثقافة المالية v5 (متوافق مع البوت v4.1)

> **تنبيه:** بناءً على طلب صاحب المشروع، تم رفع `bot/answers.txt` إلى هذا المستودع العام، ولذلك أصبح بنك الإجابات متاحًا علنًا. لا تضع داخله أي بيانات دخول أو أسرار إضافية.

واجهة ويب فوق نفس محرّك البوت (`core`): دخول بكود وباسورد، تقدم حي بنفس معلومات بطاقة البوت
(المرحلة، النشاط الحالي، النسبة الكلية، الوحدات، تقدم الاختبار، السرعة، الوقت المتوقع)، طابور، إيقاف بتأكيد، وسجل جلسات.

## الجديد في v5
- **الرجوع للحل بعد قفل الصفحة:** الحل بقى مستقل عن اتصال المتصفح. لو قفلت الصفحة أو النت قطع وفتحتها تاني، بترجع لنفس التقدم (أو للنتيجة النهائية لو خلص، محفوظة ٣٠ دقيقة — `RESULT_TTL_MIN`). ولو فتحت من نفس المتصفح وبدأت بنفس الحساب وهو شغّال، بيرجعك له بدل رسالة خطأ.
- **إعادة اتصال تلقائية** لو الـ WebSocket اتقطع (حتى ١٠ محاولات)، وفيه `GET /api/job/{id}` كمسار احتياطي.
- **بث أخف:** السيرفر بيبعت عند التغيير فقط + نبضة كل ٥ ثواني (كان رسالة كل ثانية)، والوقت بيعدّ محلياً في المتصفح.
- **الواجهة:** نسبة التقدم في عنوان التبويب، إشعار متصفح عند الانتهاء لو التبويب مخفي، زر «نسخ الأسئلة الناقصة»، ومتوسط ثواني/سؤال في الملخص.
- اختبارات جديدة: `tests/test_resume.py` (بمحرّك مزيّف، من غير متصفح ولا منصة): `BOT_DIR=/path/to/finbot_v4_1 pytest tests`.

> **السرعة:** الموقع بيستخدم نفس محرّك Playwright بتاع البوت، فسرعة الحل **نفس سرعة البوت**.
> الأسرع بكتير يحتاج محرّك HTTP مباشر (بدون متصفح) — شوف «أداة تسجيل الـ API» تحت.

## الهيكل
```
finbot_web/
├── main.py            ← FastAPI + WebSocket
├── webprogress.py     ← نموذج التقدم (نفس منطق progress.py في البوت)
├── pw_speed.py        ← قياس/أدوات Playwright اختيارية (كلها مقفولة افتراضياً)
├── capture_api.py     ← يسجّل طلبات الـ API من تشغيل البوت (انسخه جوه مجلد البوت)
├── static/index.html  ← الواجهة
├── tests/             ← اختبارات مستقلة
├── Dockerfile, railway.json, .dockerignore, .env.example
└── bot/               ← محرّك finbot_v4_1 والأصول وبنك الإجابات
```

## التشغيل محلياً
```bash
cp -r /path/to/finbot_v4_1/* bot/   # من غير .env و bot.db
cp .env.example .env
pip install -r requirements.txt && playwright install chromium
python main.py                      # http://localhost:8000
```

## النشر على Railway
1. ملف `bot/answers.txt` موجود داخل المستودع ويدخل صورة Docker تلقائيًا. لا تضع داخله أي توكن أو كلمة مرور.
2. ارفع المستودع إلى GitHub، ثم في Railway اختر **New Project ← Deploy from GitHub**.
3. أضف **Volume** على المسار `/data`.
4. المتغيرات: `DB_PATH=/data/web.db` و`TRUST_PROXY=1` و`MAX_JOBS` (حسب الرام) — والباقي افتراضي. شوف `.env.example`.
5. Settings ← Networking ← Generate Domain. الـ healthcheck على `/health`.
- خدمة واحدة فقط (Replicas = 1): حالة الطابور في الذاكرة. ولا تحط `BOT_TOKEN`.

## معرفة سبب البطء
بعد كل حل `core` بيطبع جدول «⏱️ زمن الخطوات»، و`main.py` بيطبعه في لوج السيرفر. وبـ `PROFILE_SLEEPS=1` بتشوف كمان
كام ثانية ضاعت في `sleep` وفي أنهي سطر.

## ⚠️ عن تسريع Playwright
`pw_speed.py` فيه حجب صور/خطوط وإلغاء animations، لكن **كلها مقفولة افتراضياً**: كاتب البوت قاس إن الحجب بيعطّل
الـ HTTP cache وممكن يعلّق شاشة تحميل المنصة (CHANGELOG v4.0/v4.1). لو جرّبت أي منها، فعّلها واحدة واحدة وقارن.

## أداة تسجيل الـ API (للمحرّك الأسرع بدون متصفح)
البوت أصلاً بيستخدم API المنصة (`/api/v1/subjects/7/curriculum`، وردّ تقديم الاختبار بشكل
`{"success":true,"data":{"response":{"passed","correct_count","total_count"}}}`)، لكن روابط الدخول وجلب الأسئلة وإرسال الإجابة مش معروفة.
1. انسخ `capture_api.py` جوه مجلد البوت جنب `core/`، وشغّل `python capture_api.py --activities 3` بحساب تجريبي.
2. هيطلع `api_capture.json` (الباسورد والـ tokens ممسوحة) — **راجعه بعينك** قبل ما تبعته لأي حد.
